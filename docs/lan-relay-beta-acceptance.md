# LAN Relay Beta 真机验收矩阵

> 状态：**未标记 Beta 可用**。必须由测试人员在真实 iPhone 与真实 Mac 上逐项记录日期、设备、iOS/macOS 版本和结果后，才能修改此结论。

| 编号 | 场景 | 操作 | 预期结果 | 记录 |
| --- | --- | --- | --- | --- |
| B01 | 同一 Wi-Fi 配对 | Mac 启用 LAN Relay，生成二维码；iPhone 输入实例 ID 后扫码 | 一次性配对成功，Keychain 保存凭据，Mac 出现配对设备和审计记录 | 待验收 |
| B02 | 二维码重放 | 对已成功二维码再次扫描 | 返回“已过期/已使用”，不得产生第二个设备 | 待验收 |
| B03 | 过期二维码 | 等待五分钟后扫描 | 返回过期错误，不创建设备 | 待验收 |
| B04 | Keychain 持久性 | 配对后强制退出并重启 App | 局域网配置仍可读取；移除配对后不可再读取 | 待验收 |
| B05 | Bonjour | 同一 Wi-Fi 打开 App 的局域网设置 | iOS 弹出本地网络授权；`_atolla._tcp` 可被发现；发现失败仍可扫码 | 待验收 |
| B06 | 热点网络 | iPhone 开启热点，Mac 接入热点，重复 B01/B05 | 二维码地址配对可用；Bonjour 不可用时不阻断二维码流程 | 待验收 |
| B07 | LAN 优先 | `auto` 模式下读取、发消息、停止任务 | 支持的请求走 LAN；状态 UI 显示局域网和最近成功时间 | 待验收 |
| B08 | 云端回退 | 断开 Mac LAN 服务后执行只读操作 | `auto` 读取回退云端；`lan_only` 显示失败 | 待验收 |
| B09 | 写入未知结果 | 在写入途中关闭 Mac 服务或切换网络 | 不自动向云端重放；提示结果未知；手动重试使用原幂等键 | 待验收 |
| B10 | 限流 | 连续触发 31 次动作、121 次读取、6 次配对 | 分别得到 HTTP 429；审计记录 `rate_limited`；服务持续可用 | 待验收 |
| B11 | 签名与来源保护 | 使用无签名、篡改签名、非私网来源请求 | 分别拒绝（401/403），审计不得泄露密钥或正文 | 待验收 |
| B12 | 设备撤销 | 在 Mac 撤销 iPhone 后重试 LAN 请求 | 后续签名请求被拒绝；`auto` 只读按策略回退云端 | 待验收 |

## Beta 门槛

1. B01–B12 全部通过，B06 至少在一台真实 iPhone 与一台 Apple Silicon Mac 上完成。
2. 没有 P0/P1 安全问题；审计中不得出现 `device_secret`、请求正文或实例解锁令牌。
3. 连续 24 小时运行期间，LAN 监听、Bonjour 发布和云端回退没有导致远程中继不可用。
4. 在 `docs/lan-relay-beta-acceptance-results.md` 记录实际证据后，才允许将产品文案改为“Beta 可用”。
