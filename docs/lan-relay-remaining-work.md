# Atolla 局域网直连未完成项与交付清单

> 盘点日期：2026-11-15
> 范围：`remote-relay/web` iPhone 应用、Mac `server` 的 LAN Relay，以及两者的局域网优先/云端回退链路。
> 不在范围：既有腾讯云 Remote Relay 的接口、服务、数据库与部署改造。历史 `docs/plan/` 中未勾选的条目不能单独作为“当前未完成”的证据，需另行按代码验收。

## 1. 当前基线

### 已完成的基础能力

- Mac 端已具备独立 LAN 监听器；当前暴露 `GET /lan/v1/health`、`POST /lan/v1/actions` 与版本化只读入口 `GET /lan/v1/reads/*`。
- 请求已具备设备 ID、时间戳、nonce、请求体 SHA-256 与 HMAC 校验；服务端拒绝非私网来源、过期签名与重复 nonce。
- LAN 监听器生命周期已接入 Mac 服务，已配对设备密钥可查询、撤销。
- iPhone 端已具备 LAN 配置页、健康检查及 `自动 / 仅局域网 / 仅云端` 三种策略。
- 移动端目前已能将下列写操作优先转为 LAN 动作：`agent.ask`、`agent.stop`、`agent.set_task_plan`、`agent.set_auto_review`、`agent.set_auto_approve_all`；LAN 失败时会继续使用既有云端请求。
- **P0-1 已完成（核心只读 Facade）**：实例、Agent、任务、消息、待审批，以及任务队列、任务计划、Agent 设置、Skills、通知偏好、引擎额度和 JEV 设置均可通过本地 Facade 读取；分页与筛选参数也受 HMAC 保护。

### 当前不能宣称已完成的能力

- 尚未实现“手机端全部功能均可 LAN 优先”。
- 尚未实现完整的逐实例通道状态与可靠自动回退。
- 尚未实现二维码配对、Bonjour 发现、Keychain 密钥保存、LAN 只读 Facade、写操作幂等和真机端到端验收。

## 2. P0：必须完成后才能宣称全量局域网直连

### P0-1：LAN 只读 Facade（已完成）

**完成内容**：已建立独立的 `/lan/v1/reads/*` Facade，直接从 Mac 的本地 Store、运行态与权限 Hub 构造 DTO；不会复用云端镜像或触发 `sync.*` 推送。移动端已对支持的读取请求采用 LAN 优先策略，未支持的读取保留云端路径。

**已完成项**：

- 新增实例、Agent、任务、消息、权限和设置读取资源；任务队列、任务计划、Skills、通知、引擎额度、JEV 等既有纯读取能力经只读动作白名单暴露。
- Facade 只允许固定资源与只读动作，不直接暴露桌面管理后台路由；查询参数被纳入 HMAC 签名，避免分页/筛选参数被篡改。
- 覆盖分页、空数据、实例或 Agent 不存在等本地读取边界；服务端已补签名查询参数的回归测试。

**遗留限制**：站点登录、站点收件邮箱、远程 OTP 状态、版本号与更新日志属于云端站点能力，当前显式保持云端，不应被误标为 LAN 可用。

**验收**：断开 Mac 的外网后，iPhone 与 Mac 同一局域网时仍可查看实例、Agent、会话、消息、任务和待审批项；抓包不出现腾讯云域名。

### P0-2：全量移动端操作迁移

**现状**：`lanActionForRequest` 仅映射 5 个 Agent 操作。任务队列、任务计划决策、审批、图片、实例解锁、通知、JEV、Agent 设置和 Skills 等仍只会走云端。

**工作项**：

- 按业务能力定义类型安全的 `RelayTransport` 接口；页面不得自行决定 LAN 或云端 URL。
- 将下列写操作逐项接入 LAN Facade，并对齐返回 DTO：
  - 实例登录、解锁、验证码状态与会话心跳；
  - 创建 Agent、Agent 设置、Skills 安装/卸载；
  - 任务队列新增、编辑、中断、继续、取消和清理；
  - 任务计划确认、拒绝、中止和恢复；
  - 权限审批决定、已读状态、查看者在线状态；
  - 聊天图片上传与消息同步；
  - 通知偏好、Bark 校验、JEV 安装/启用/卸载。
- 不能映射到 Mac 本地业务能力的接口必须显式标记为“仅云端”，而非静默回退。

**验收**：以 API 清单逐项验证，LAN 可用时每个受支持操作均由 Mac 执行，且移动端展示与云端操作一致的结果或可理解错误。

### P0-3：写操作幂等与安全回退（已完成，受云端协议边界限制）

**完成内容**：`POST /lan/v1/actions` 现在要求受 HMAC 保护的 `X-Atolla-Idempotency-Key`。Mac 以“已配对设备 + 键”暂存运行中与已完成动作，以动作名和请求体摘要检测冲突；重复请求会等待或复用第一次的完整响应，不能再次进入执行器。

**安全回退规则**：移动端在 LAN 健康检查失败、且业务动作尚未发出时，`自动`策略可以继续使用既有云端请求。一旦 LAN 动作已发出，任何超时、断连或 5xx 都会显示“结果未知”，**不会**自动重放到云端；这避免在云端尚未具备兼容幂等协议时重复创建聊天、任务或审批决定。

**已完成项**：

- 客户端为当前已映射的 LAN 写操作生成随机幂等键，并将其写入 HMAC canonical 请求内容与请求头；结果未知时会在 10 分钟内保留同一语义请求的键，手动重试可命中 Mac 缓存结果；得到确定结果后立即生成新键。
- Mac 端对同键同请求实现并发合并、完成结果重放、冲突拒绝和有限 TTL 清理；缺失或非法键会被拒绝。
- 故障注入已覆盖“首个动作仍在执行时的并发重试”及“首个动作完成后响应丢失、客户端使用同键重试”；两种情况的执行器调用次数均为 1。
- `lan_only` 不回退；`auto` 仅允许预检阶段回退云端，动作发出后始终保守失败。

**遗留边界**：腾讯云命令队列未提供可复用的幂等键字段，且本期约束不修改云端协议。因此不能实现“LAN 已执行但结果未知后仍自动回退云端”；若未来要恢复该能力，必须先在云端命令存储和结果查询接口中实现同一幂等契约。

**验收**：在 LAN 操作已到达 Mac 但响应被人为丢弃的场景下，客户端不会自动云端重放；以同一幂等键重试时，Mac 返回缓存结果且不会再次执行。

## 3. P1：配对、发现与通道状态

### P1-1：安全配对与设备密钥存储

**现状**：iPhone 端依赖手动输入 Mac URL、设备 ID 和密钥，密钥保存在 WebView `localStorage`；这不符合设计中的一次性配对与 Keychain 存储。

**工作项**：

- Mac 创建短时、单次使用的配对会话；二维码仅包含地址、端口、会话 ID、挑战值和协议版本，不包含长期密钥。
- iPhone 扫码完成配对，密钥写入 iOS Keychain；移除 `localStorage` 中的长期密钥。
- Mac 端提供已配对设备列表、权限范围、最后在线时间和立即撤销；撤销后请求必须立即失效。
- 为旧的手动输入方式保留仅开发调试入口，正式界面不展示长期密钥字段。

**验收**：密钥不出现在页面、日志、二维码或 WebView 存储中；撤销后该 iPhone 的健康检查和所有业务请求均被拒绝。

### P1-2：发现与逐实例路由

**现状**：无 Bonjour 广播/扫描；策略是全局配置，尚未形成“实例级”通道状态、连续失败阈值、退避或网络变化处理。

**工作项**：

- Mac 使用 Bonjour 发布 `_atolla._tcp`，TXT 仅发布协议版本、端口、实例短 ID 和临时发现标识。
- iPhone 使用原生 Bonjour 发现；发现失败时对已配对地址进行受限健康检查，并支持二维码地址直连。
- 为每个实例维护 `lan / remote / switching / unavailable` 状态、最近成功时间、连续失败次数和下一次退避时间。
- 在启动、前台恢复、网络变更、Mac 休眠恢复后触发受控探测；切换时取消旧轮询，不丢失输入中的草稿。

**验收**：普通 Wi-Fi 与 iPhone 个人热点下均能发现或通过二维码连接；LAN 中断后仅影响对应实例，其余实例按各自通道继续工作。

### P1-3：状态展示与排障体验

**工作项**：

- 在设置页展示当前通道、最近一次检查、失败原因和“重新发现/重新检查”操作。
- 在实例页和会话页以文字 + 图标展示“局域网直连 / 云端中继 / 正在回退 / 不可用”，并提供 VoiceOver 标签。
- `lan_only` 失败时提供可执行排查项，不暴露不必要的 Mac IP；自动回退时使用非阻塞提示。
- 修正文案：当前设置页仍写着“业务请求仍使用云端中继”，应在业务迁移完成后替换为真实能力范围。

## 4. P1：LAN 服务生产化

### P1-4：监听边界、限流与审计

**现状**：监听器绑定 `0.0.0.0` 后通过来源 IP 判断私网；虽可阻止公网来源，但不满足“仅绑定启用私网接口”的设计目标。当前没有按操作分类的限流与安全审计。

**工作项**：

- 枚举并绑定用户选定的私网接口地址，处理 IP 变化、IPv6、热点地址变化和监听重启；不得依赖 `0.0.0.0` 作为最终实现。
- 对健康检查、读取、写入、上传和审批分别限流，并设置请求体大小、并发数和上传超时上限。
- 记录拒绝原因（未知设备、过期时间戳、重放 nonce、签名错误、非私网来源、限流），日志中不写入密钥和正文。
- 为 LAN 端点制定稳定错误响应格式与错误码，避免将内部错误直接返回给 App。

### P1-5：HTTP 风险与权限边界

**工作项**：

- 继续在 Mac 和 iPhone 显著提示：HTTP 仅适用于可信网络，内容不具备保密性。
- 禁止长期密码、云端 JWT 和设备密钥出现在正文、查询参数或日志中。
- 明确最小设备权限模型，例如只读、操作、审批；配对设备默认最小权限。
- 评估后续自签名 TLS + 证书指纹固定路线；这不是本期 HTTP 交付的阻塞项，但必须在安全文档中保留迁移路径。

## 5. P2：测试、构建与交付

### P2-1：自动化测试

- 服务端：签名、重放、撤销、幂等、并发审批、限流、接口绑定、DTO 契约和错误码测试。
- 移动端：Transport 选择、失败阈值、退避、回退一次、草稿保留、`lan_only` 行为及 Keychain mock 测试。
- 端到端：LAN 可达时无云端请求；LAN 中断后正确回退且不重复写入；恢复后重新切回 LAN。

### P2-2：真机验收矩阵

| 场景 | 必验结果 |
| --- | --- |
| 同一 Wi-Fi | 发现、配对、全量读取/写入、状态展示正常 |
| iPhone 个人热点 | Bonjour 可用时自动发现；不可用时二维码地址可连通 |
| Mac 无外网、LAN 正常 | 手机端核心功能不依赖腾讯云 |
| LAN 中断 | 自动回退一次，业务无重复写入 |
| Mac 休眠/唤醒与 IP 变化 | 受控重连，页面不崩溃、不泄露密钥 |
| 设备撤销/重放请求 | 请求被拒绝并产生可检索审计记录 |

### P2-3：iOS 构建交付

- 用真实开发团队、Bundle ID 与有效 provisioning profile 完成真机签名构建；此前出现的 `ProcessProductPackaging` 失败属于签名配置问题，不能以 Web 构建成功替代真机验证。
- 固化 `cap sync`、Pods 安装、Xcode/CLI 路径检查、Debug 真机安装与 Release Archive 的操作说明。
- 将生成的 Xcode 构建产物保持在 `.gitignore`，不将 `build-device` 等派生文件纳入提交。

## 6. 推荐实施顺序

1. 定义 LAN DTO、错误码和 `RelayTransport` 契约，先完成 P0-1 的只读 Facade。
2. 为全部写操作加入幂等模型，再批量实施 P0-2 的动作迁移；禁止先扩大自动回退范围。
3. 完成 P0-3 并以故障注入验证不重复执行。
4. 实施二维码配对、Keychain、Bonjour 与逐实例路由状态。
5. 补齐限流、审计、状态 UI 和真机验收矩阵，最后才将功能标记为 Beta 可用。

## 7. 完成定义

只有同时满足以下条件，才能将“局域网优先、云端自动回退”标为完成：

- 当前 iPhone App 的每项功能都有明确的 LAN 支持、明确的云端限定，或明确的产品下线决定；不存在静默遗漏。
- LAN 可用时，支持的请求不访问腾讯云；LAN 不可用时业务只执行一次且安全回退。
- 设备配对、密钥存储、撤销、审计与限流已通过自动化和真机验证。
- 同一 Wi-Fi、个人热点、网络切换、Mac 休眠恢复和异常回退均有可复现的验收记录。
