# 移动端任务队列（remote-relay App）

## 1. 背景

PC 管理台已落地持久化任务队列（打断 / 入队 / paused LIFO / 右侧轨）。手机中继 App 仍走旧路径：忙碌时服务端 **静默入队**，用户无法选择打断，也看不到队列进度。需要与 PC **共用同一套状态机与落库**，在手机侧补齐轻量选择与列表能力。

关联文档：[`2026-10-28-数字人任务队列.md`](./2026-10-28-数字人任务队列.md)（PC 一期；§8.15 原「手机仅默认入队」由本文覆盖升级）。

## 2. 开发目标

- 手机对话页忙碌再发时弹出 ActionSheet：**打断优先** / **加入队列**，横排 + **5s 进度条**。
- **超时默认：打断**（与 PC 弹层一致）；**不需要**打断二次确认。
- 顶栏/忙态旁角标展示活跃队列数；半屏 Bottom Sheet 查看列表、取消 queued/paused、hold 时「继续队列」。
- 空闲直发不入队；真相源仍为 `agent_task_queue`；禁止手机旁路 Ask 打乱状态机。
- 旧客户端无 `mode` 时服务端仍 **默认入队**（兼容未升级 App）。

## 3. 实现范围

### 本次实现

- remote-relay Web/App：`ChatHistory` 发前拦截；`TaskQueueChoiceSheet`（忙碌二选一）；`TaskQueueListSheet`（半屏列表）；角标。
- 中继协议：透传 task-queue 相关 Mac 命令；`agent.ask` 支持 `mode: direct | enqueue | interrupt`。
- Mac Go：`AskManagedBackground` / remotebridge 按 `mode` 分支；暴露 list / enqueue / interrupt / continue / cancel（与 admin API 语义对齐）。
- i18n：中继 `messages.ts` 补 `tq.*`。
- Toast：入队成功提示「已加入队列」；连跑 Bark `silent_notify` 行为与 PC 一致。

### 本次暂不实现

- PC 式右侧可拖拽抽屉 / 呼吸灯轨 hover。
- 队列内拖拽排序、编辑正文。
- 手机 @ 多人「生成群聊」offer（手机本无此路径）。
- 打断二次确认弹窗。
- 跨数字人共享队列。

## 4. 技术设计

### 4.1 产品规则（已拍板）

| 项 | 决策 |
|----|------|
| 忙碌弹层 | 横排：打断 \| 入队；顶部 5s 进度条 |
| 超时默认 | **打断**（非入队） |
| 打断确认 | **不需要**二次确认 |
| 空闲直发 | 不写队列行 |
| Stop | running → cancelled + hold；需「继续队列」或再发才恢复 |
| 旧 App | 无 mode → 服务端 enqueue 兜底 |

### 4.2 UI 结构

1. **忙碌 ActionSheet**（composer 上方 / 底部 sheet）  
   - 进度条 + 倒计时文案（「n 秒后默认打断并优先」）  
   - `[打断优先]`（标默认）`[加入队列]`  
   - 取消：关闭并回填输入框，不停当前任务  

2. **角标**  
   - `active = queued + paused + running`（hold 时至少显示 1 或单独 hold 态）  

3. **半屏列表 Sheet**  
   - 项：状态点 + 问题摘要 + 取消（queued/paused）  
   - hold：提示 +「继续队列」  
   - 近 N 条 done/failed/cancelled 可选展示（与 PC doneKeep 对齐）

### 4.3 协议与服务端

**中继 → Mac 建议 actions（名称可微调，语义固定）：**

- `agent.task_queue.list`
- `agent.task_queue.enqueue` `{ question, attachments }`
- `agent.task_queue.interrupt` `{ question, attachments }` → 返回 `task_id`，再由客户端或服务端拉起 Ask
- `agent.task_queue.continue`
- `agent.task_queue.cancel` `{ task_id }`
- `agent.ask` 扩展：`mode?: 'direct' | 'enqueue' | 'interrupt'`；`task_id?`；`resume_prefix?`

**AskManagedBackground 改造：**

```text
busy + mode=interrupt → InterruptPrefer + AskWithTask
busy + mode=enqueue   → Enqueue（不 stop）
busy + mode 缺省      → Enqueue（旧客户端）
idle + mode 缺省      → 直发 Ask（不入队）
```

续跑：手机无 SSE，继续服务端 `autoRunClaimedTaskQueueItem`；镜像推送刷新角标/消息。

### 4.4 前端模块（remote-relay/web）

- `pages/ChatHistory.tsx`：`busy` 发送拦截 → ChoiceSheet  
- `components/TaskQueueChoiceSheet.tsx`  
- `components/TaskQueueListSheet.tsx`  
- `api.ts`：封装 list/enqueue/interrupt/continue/cancel  
- 轮询：对话打开时随现有 POLL 或 4s 刷 list；推送到达时刷新  

### 4.5 与 PC 对齐点

- 同一张表、同一 pause LIFO、同一 silent_notify  
- 系统恢复前缀文案不变  
- waiting 视为阻塞 running：可入队、可打断，不可静默出队下一条  

## 5. 变更影响

| 原设计 / 现状 | 新设计 |
|---------------|--------|
| 手机忙碌一律服务端静默入队 | 新 App 弹层可选；默认 5s 后打断 |
| PC §8.15「手机默认入队、无 UI」 | 升级为本方案；旧客户端仍默认入队 |
| 仅 admin HTTP 写队列 | 中继命令等价写入口 |
| 手机无队列可见性 | 角标 + 半屏列表 |
