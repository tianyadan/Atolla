# 数字人引擎模型切换（Claude / Codex / Cursor）

## 1. 背景

Atolla 数字人对话已通过各引擎 CLI 的 `--resume` / `exec resume` 续聊，但**从未传入 `--model` / `-m`**，模型完全依赖本机 CLI 默认配置。

产品需要：在平台内为数字人选择（或手输）模型；切换后**同一会话 resume 时也生效**。

约束（已确认）：

- **不自造模型名清单**；能从官方/本机探测到的才作为下拉选项。
- **Claude**：本环境多用 **ccswitch** 等网关，常无 Anthropic API Key → `GET /v1/models` 可能不可用 → **必须允许自定义手输** model id。
- 模型切换仅在**当前引擎内**进行（不跨 Claude↔Codex↔Cursor 换引擎）。

官方能力结论（调研）：

| 引擎 | resume + 切模型 | 官方目录来源 |
|------|-----------------|--------------|
| Claude Code | `--resume` + `--model`（官方说明：resume 默认可保留旧模型；显式 `--model` 可覆盖） | [model-config](https://code.claude.com/docs/en/model-config) 别名；可选 Anthropic `GET /v1/models` |
| Codex | `exec resume` 支持 `-m` / `-c model=` | [Learn · Models](https://learn.chatgpt.com/docs/models) 文档中的 CLI id（如 `gpt-6.2-sol`） |
| Cursor Agent | `--resume` + `--model` | 本机 `agent --list-models` / `agent models`（账号相关） |

## 2. 开发目标

1. 每个数字人可持久化一个 `model`（可空 = 用引擎默认）。
2. 每次 Ask（含 resume、群聊 Speak、invoke 子调用若走同一 Runner）把该 model 传给对应 CLI。
3. 提供「按引擎拉模型列表」API：能探测则返回官方/本机列表；不能探测则返回空列表 + `allow_custom=true`。
4. PC 设置页（及可选 App 实例设置）可选模型或手输自定义 id 并保存。

## 3. 实现范围

### 本次实现

- DB：`managed_agents.model`（VARCHAR，可空）。
- Store / Create / Update / Clone / List JSON 读写 `model`。
- Agent CLI 层：Claude / Codex / Cursor 传 model（含 resume 路径与 warm runtime）。
- Service Ask 主链路（`askManagedCore` → `invoke` 内引擎分发）注入 `a.Model`。
- API：`GET /api/admin/engines/:engine/models`；`PATCH/PUT` 更新数字人时接受 `model`。
- PC：数字人设置里「模型」选择器 + 自定义输入（Claude/ccswitch 场景重点）。
- 远程中继（可选同迭代）：settings 字段透传 + models RPC（手机改模型）。

### 本次暂不实现

- 跨引擎换模型 / 换引擎自动清 session。
- 切模型后自动改 `context_window_tokens`。
- 爬取 OpenAI Learn 页面作为 Codex 唯一实时源（可先用文档固化的推荐 id + 自定义；后续再做刷新器）。
- 会话级临时模型（仅本轮、不落库）——若要做，列为二期。
- 强制校验 model 必须在白名单（与「允许自定义」冲突）。

## 4. 技术设计

### 4.1 数据

**表 `managed_agents`**

```sql
ALTER TABLE managed_agents ADD COLUMN model VARCHAR(191) NOT NULL DEFAULT '';
```

- 空字符串：不传 `--model` / `-m`，沿用 CLI/config 默认。
- 非空：原样传给 CLI（不做 Atolla 侧改写；ccswitch 的名字由用户负责）。

**涉及文件**

- `server/internal/store/store.go` — DDL 迁移条目
- `server/internal/store/managed_agents.go` — `ManagedAgent` / `ManagedAgentInput` / SELECT / INSERT / UPDATE / Clone

### 4.2 模型目录服务

新增包或文件建议：`server/internal/service/engine_models.go`（或 `server/internal/agent/models_catalog.go`）。

```text
ListEngineModels(engine) -> {
  engine, source: "cli"|"api"|"docs"|"none",
  allow_custom: bool,
  default?: string,
  items: [{ id, label }]
}
```

规则：

| engine | 行为 | allow_custom |
|--------|------|--------------|
| `agent` | 执行 `agent --list-models`（或 `agent models`），解析 `id - label` | true（账号未列出的也可手输） |
| `claude` | 若存在 `ANTHROPIC_API_KEY`（或可安全读到的 key）→ `GET /v1/models`；否则 `source=docs` 仅返回官方 **alias**（`sonnet/opus/haiku/fable/...`），**不做自造全量 ID 表** | **true（必须）** |
| `codex` | 优先读 `~/.codex/models_cache.json`（`visibility=list`）；否则 docs 快照兜底 + 允许自定义 | true |

超时：CLI/API 建议 8–15s；失败时降级为 `items=[]` + `allow_custom=true` + `detail` 说明。

**涉及文件**

- 新建：`server/internal/service/engine_models.go`（+ 单测解析 list-models 输出）
- `server/internal/handler/handler.go` — 注册路由
- 新建或并入：`server/internal/handler/engine_models.go` — `AdminEngineModelsGet`

路由建议：

```http
GET /api/admin/engines/:engine/models
```

`engine` ∈ `claude|codex|agent`（与 `RepairEngineName` 一致）。

### 4.3 CLI 传参（核心）

在现有 args 组装处追加 model（trim 后非空才加）：

| 引擎 | 文件 | 改动点 |
|------|------|--------|
| Claude | `server/internal/agent/agent.go`（`AskStreamWithImagesPhase`） | `--model <id>`；`warm_runtime.go` 同步 |
| Cursor | `server/internal/agent/generic.go`（`CursorCLIArgs`） | `--model <id>` |
| Codex | `server/internal/agent/codex.go`（`exec` 与 `exec resume`） | `-m <id>`（或等价 `-c model="..."`） |

签名建议：各 Ask* 增加 `model string` 参数，或在现有 opts 结构体中增加字段，避免全局状态。

**调用链必须打通**

- `server/internal/service/invoke.go` — 引擎分发处读 `a.Model` 传入
- `server/internal/service/managed_agents.go` / `askManagedCore` — 确保主会话 Ask 走到上述路径
- 群聊 `SpeakInGroup`、scheduler、workflow 等复用 invoke/ask 的路径：跟同一入口，避免旁路漏传

### 4.4 数字人 CRUD / Handler

- `AdminAgentsUpdate`：解析 body `model`（string；允许显式 `""` 清空）
- Create / Copy：可选带 `model`；复制员工时拷贝源 `model`
- List / Get：JSON 返回 `model`

**涉及文件**

- `server/internal/handler/managed_agents.go`
- `server/internal/store/managed_agents.go`
- 招聘/克隆相关：`server/internal/service/agent_clone.go`、talent market create（若写 managed_agents）

### 4.5 远程中继（建议同迭代或紧随）

- `remotebridge/runtime.go`：`ListEngineModels` / agent settings 含 model
- `remotebridge/registry.go` + actions：`engines.models.get` / settings update
- `remote-relay/server/src/routes/site.ts` + `web/src/api.ts`
- App：`InstanceSettings` 或数字人设置页增加模型控件

### 4.6 前端（PC）

**设置入口**：`web/src/ManagedAgents.jsx` 数字人设置弹窗（已有 `contextWindowDraft` 的「基础」区旁）。

UI 行为：

1. 打开设置 → `GET /api/admin/engines/{selected.engine}/models`
2. `items` 非空 → Select；另提供「自定义」输入框（或 Select 最后一项「自定义…」）
3. `items` 空或 `allow_custom` → 仍显示输入框；placeholder 提示 ccswitch / 官方 id
4. 保存走现有 `saveRules` / update API，body 增加 `model: modelDraft`
5. 对话头可只读展示当前 model（小字，可选）

**涉及文件**

- `web/src/ManagedAgents.jsx`（设置表单状态、保存、加载 catalog）
- 文案：`web/src/i18n/messages.js`（如有）
- 样式：沿用 `ma-settings-*`，尽量不新造体系

### 4.7 关键规则

1. **空 model**：CLI 不加 `--model`/`-m`。
2. **非空**：原样传递；Atolla **不做**「必须在 catalog」校验。
3. **换引擎**：保留或清空 model？**建议清空**（旧 id 对新引擎无意义），在 Update engine 流程里处理；若当前产品禁止改引擎则可不做。
4. **Resume**：每次 Ask 都带当前落库 model，保证设置页改完下一轮即生效。
5. **错误展示**：CLI 报 unknown model 时，沿用现有引擎错误压缩展示，提示检查模型名 / ccswitch。

### 4.8 核心流程

```text
用户打开设置
  → GET /engines/:engine/models
  → 选择或手输 model → PUT /agents/:id { model }
  → 下次 Ask
       → Store 读 a.Model
       → invoke/Claude|Codex|Cursor args 追加 model
       → --resume <sid> 同时带 --model/-m（若非空）
```

## 5. 变更影响

| 模块 | 影响 |
|------|------|
| `managed_agents` schema | 新列 `model`；旧行默认 `''` 行为与现网一致 |
| Ask / resume | 仅当配置了 model 时 CLI 参数变化 |
| 设置页 | 新增控件；保存 payload 多字段 |
| 镜像 / App | 若做中继，settings 与列表需带 `model` |
| 上下文圆环 / 窗口档位 | 本迭代不联动 |

**原设计 vs 新设计**

- 原：模型只由本机 `~/.claude` / `~/.codex/config.toml` / Cursor 账号默认决定。
- 新：平台可覆盖；探测不到官方全量列表时（尤其 Claude+ccswitch）以**自定义手输**为准，下拉仅为辅助。
