# PC 群聊（@ 多人 5s 岔路 + 主持开会）设计

日期：2026-10-22  
状态：**定版**（对齐 X「Grok Bot in Chat」共享时间线）  
实现计划：[docs/superpowers/plans/2026-10-22-pc-group-chat.md](../plans/2026-10-22-pc-group-chat.md)

## 0. 定版结论（对照 Grok Bot）

依据 X 官方 [About Grok](https://help.x.com/en/using-x/about-grok)（2026）：

| Grok Bot（现网） | Atolla 定版 |
|--|--|
| 把 Bot **拉进同一条 X Chat**，读加入后的全员消息 | 建 **群共享 conversation**，全员发言进同一时间线 |
| 在群里直接回帖，而不是并行私聊再汇总 | **串行点名发言**进同一 feed；禁止首轮走旧 `invokeAllParallel` |
| 工具动作：允许一次 / 总是允许 / 拒绝 | 复用现有 Permission Gateway（人审/自动） |
| 1:1 Grok 导航栏助手另线存在 | 保留现有单人对话 + `@` 并行岔路（超时默认） |

**产品双路径（定死）**：

1. **默认（超时 / 不点）**：现有 `@` → 并行委托 → 引用回填 → 主持人汇总（隔离执行，适合「分头干活」）。  
2. **显式「生成群聊」**：**Grok 式共享时间线** + 群主主持串行开会（适合「开会讨论」）。

不做：把并行 invoke 伪装成群聊；不做移动端群聊 MVP。

## 1. 目标

在**不推翻**现有「数字员工对话框内 `@` → 并行委托 → 引用回填 → 主持人汇总」的前提下，增加一条可选路径：

- 用户在某数字员工对话里 `@` 多名同事并发送时，弹出 **5 秒**「是否生成群聊」；
- 超时不操作 → **仍走原有**并行机制；
- 点击「生成群聊」→ 在 PC「群聊」菜单建群，用 **Grok 式共享时间线 + 主负责人主持开会** 回答本条需求。

首期只做 **PC 管理台**；移动端 Hub「群聊」继续占位。

## 2. 非目标（MVP）

- 移动端群聊 / remote-relay 镜像群消息
- 与「项目协作」Workflow 图打通
- 群文件、语音、复杂权限矩阵
- 自动无限扩群（人数有硬上下限，见下）

## 3. 产品规则（已确认）

### 3.1 触发与 5 秒面板

| 条件 | 行为 |
|------|------|
| `@` 解析后成员集合（见 3.2）人数 **不在 3～5** | 不弹面板；若 ≥2 仍可走原并行，或提示「群聊需 3～5 人」（实现上：仅当可建群人数 ∈[3,5] 才弹面板；否则直接旧逻辑） |
| 人数 ∈ **[3, 5]** | 发送后拦截，底部面板滑到输入框上方 |
| 面板内容 | 说明文案 + **水平进度条 5s** + **「生成群聊」** |
| 超时 / 未点 | 关闭面板 → **原有** `ParseMentions` + `invokeAllParallel` + 汇总 |
| 点击生成群聊 | 取消倒计时 → **不跑**旧 invoke → 建群并进入群聊页，注入本条用户问题开场 |

### 3.2 成员与群主

- **群主（主负责人）**：用户当前所在对话窗口对应的数字员工；支持日后 **转让群主**。
- **成员集合** = `unique(群主 ∪ 本条 @ 到的数字员工)`。
- **人数硬限制**：成员总数 **3～5**（含群主）。过少/过多不提供「生成群聊」岔路。
- `@` 列表若已含群主，去重，不重复占坑。

### 3.3 群名

自动生成，例如：`协作 · {需求截断≤20字}` 或 `{群主名}的会议 · {MMdd-HHmm}`。MVP 可先不可改名；转让群主不强制改名。

### 3.4 群内开会（主持模式 B）

首轮固定流水线：

```text
用户问题 → 写入群共享时间线
  → 群主先发言（拆任务 / 点名顺序；派活时综合：名称、系统提示词、技能；若该成员有群内标签则以标签为准）
  → 按点名 **串行** 调用成员（每人一条进同一时间线）
  → 群主收尾汇总
之后用户可在群内继续发言，并可 @ 指定成员
```

### 3.5 群内标签（覆盖原人设）

- 可对群内任意成员编辑 **群内标签**（短文本/结构化说明，存群成员维度）。
- **有标签**：该成员在本群发言时，**忽略**其原系统提示词 + 技能，仅按标签 + 群规则构造系统侧指令。
- **无标签**：仍用原名称/系统提示词/技能（群主派活时也按此综合判定）。

### 3.6 记忆与引擎 Session

| 角色 | 规则 |
|------|------|
| **群共享背景** | 仅从 **群主** 主会话截取最多 **10000 字** 文本，写入群的 `shared_background`；**全体成员共享** 这份背景（避免每人各带 10k 撑爆窗口） |
| **其它成员** | 建群时 **不** 各带 10k 个人上下文 |
| **发言时引擎** | 成员在群内被点名/被 `@` 发言时，**继续 resume 各自主会话的 `engine_session_id`**（沿用当前 CLI session 工作，减少失忆） |
| **展示** | 气泡落在 **群共享 conversation**；与个人主会话 UI 分离 |

背景与 resume 并存：背景给「会议材料」；resume 保「工具/仓库连续工作状态」。

## 4. 数据模型（建议）

```text
group_chats
  id, name, owner_agent_id, shared_background TEXT,
  shared_conversation_id,   -- 群时间线
  created_from_agent_id,    -- 建群时所在窗口
  seed_question TEXT,       -- 开场用户问题
  status (active|archived), created_at, updated_at

group_chat_members
  group_id, agent_id, role (owner|member),
  group_tag TEXT NULL,       -- 有则覆盖原 prompt+skills
  joined_at, UNIQUE(group_id, agent_id)
```

消息：复用现有 `messages` 表，挂在 `shared_conversation_id`；`meta_json` 可带 `speaker_agent_id` / `speaker_name` 标明发言人。

转让群主：更新 `owner_agent_id` + 成员 `role`。

## 5. API / 服务（PC）

示意（最终以实现为准）：

- `POST /api/admin/group-chats` — 建群（成员、seed、从群主截 10k 背景）
- `GET /api/admin/group-chats` — 列表
- `GET /api/admin/group-chats/:id` — 详情 + 成员 + 消息
- `POST /api/admin/group-chats/:id/ask` — 用户在群内发言（SSE；可含 @）
- `POST /api/admin/group-chats/:id/transfer-owner` — 转让
- `PATCH /api/admin/group-chats/:id/members/:agentId` — 改 `group_tag`

建群后自动跑 **首轮主持流水线**（可与 ask SSE 同通道推送 `chunk` / `speaker` / `done`）。

成员被点名发言：内部类似 `AskManagedIsolated`，但：

- 展示写入群 conversation；
- resume 用该 agent **主会话** engine session；
- system 侧注入：群规则 + **共享背景** +（标签或原 prompt/skills）+ 主持指令。

## 6. PC 前端

### 6.1 数字员工对话（[ManagedAgents.jsx](web/src/ManagedAgents.jsx)）

- `sendQuestion` 前：`ParseMentions` 等价逻辑算 `unique(当前员工 ∪ @)`；
- 若人数 ∈[3,5]：打开底部 Sheet（进度条 + 生成群聊），挂起真正请求；
- 超时 → 现有 ask SSE；
- 点生成 → `POST group-chats` → 切到群聊视图。

### 6.2 群聊菜单（PC 主导航新增）

- 管理台主导航增加 **「群聊」** 菜单（与「数字员工 / 项目协作」等同级，见 [App.jsx](web/src/App.jsx) 的 nav tabs）。
- **群列表**：每群展示群名、人数、最近活动；成员区用各数字员工自己的 **`jelly_color` 像素水母** 并排/叠放预览（颜色互不相同、与员工档案一致，复用现有 `JellyAvatar`）。
- **群详情 · 成员条**：每位成员 = 小水母 + 名称；群主有标识；可点开编辑群内标签 / 转让群主。
- **群详情 · 时间线（谁在说话）**：
  - 每条助手/成员发言气泡旁（或气泡顶栏）展示：**小尺寸像素水母**（该 `speaker` 的 `jelly_color`）+ **小字体名称**；
  - 用户消息仍用现有「你」样式，不必水母；
  - 系统/状态条可不带头像。
- 输入框：支持 `@` 群内成员（候选列表同样小水母 + 名）。

视觉对齐现有管理台数字员工列表的水母规范（`ma-avatar-sm` / 更小一档如 18～22px 用于气泡旁），避免另做一套头像体系。

## 7. 与现有 `@` 的关系

```mermaid
flowchart TD
  send[用户发送含@的消息]
  parse[解析成员集合含当前窗口员工]
  size{人数在3到5?}
  sheet[5s底部面板]
  old[原并行invoke加汇总]
  create[创建群聊写共享背景]
  meet[群主主持串行开会]
  send --> parse --> size
  size -->|否| old
  size -->|是| sheet
  sheet -->|超时未点| old
  sheet -->|生成群聊| create --> meet
```

## 8. 验收（MVP）

1. `@` 后成员总数 2 人：不弹群聊面板，行为与现网一致。  
2. 总数 3～5：弹 5s 面板；不点 → 旧并行；点了 → 群列表出现新群，时间线有用户问题。  
3. 首轮：群主发言 → 成员串行 → 群主收尾；气泡带发言人。  
4. 仅群主贡献 ≤10000 字进 `shared_background`；其它成员无各自 10k。  
5. 成员有群内标签时，发言不再带原技能/原系统提示词。  
6. 转让群主后，后续主持角色切换。  
7. PC 有「群聊」菜单；列表可见各成员不同颜色水母；群内气泡旁为小水母 + 小字名称标明发言人。  
8. 移动端无回归要求（不做）。
