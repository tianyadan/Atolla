# Atolla 产品手册重构设计

## 意图

将当前只有“对话”分类的产品手册，扩展为能系统解释 Atolla 核心产品能力、用户操作路径和代码/业务调用链的结构化手册。手册不是简单功能列表，每篇要能说清“用户看到什么”、“系统如何实现”、“边界在哪里”。

## 范围

保留并扩展以下九个一级模块：

1. 平台启动与工作引擎。
2. 数字员工生命周期。
3. 对话与任务执行。
4. 安全与命令审批。
5. 多数字员工协作。
6. 记忆、上下文与知识继承。
7. 技能与外部资源。
8. 远程中继与多端协同。
9. 通知、灵动岛与运行可观测性。

## 明确排除

- “项目协作流程图”不再进入产品手册，视为废案。
- 不编写 Workflow Canvas、节点编排、项目运行恢复、节点重试等用户手册。
- 不在其他文章中引导用户“改用项目协作”。
- 本次不删除现有 Workflow 产品代码，仅处理产品手册内容。

## 内容标准

每篇手册至少包含：

1. 功能定位与适用场景。
2. 用户操作流程。
3. 一张 Markdown `text` 流程图，展示业务流或代码调用链。
4. 关键状态、数据或决策点。
5. 失败、降级、安全和能力边界。

内容必须以当前代码为依据，不把设计稿、旧计划或尚未落地的能力写成已实现功能。

## 结构设计

- `web/src/productManual.js` 只负责一级分类、文章顺序和汇总导出。
- `web/src/productManualContent/` 按一级模块拆分九个内容文件。
- 每个文件导出该分类的文章数组，文章继续使用 Markdown 字符串，复用当前 `marked` 渲染链。
- 现阶段使用 fenced `text` 流程图，不新增 Mermaid 依赖。

## 现有内容迁移

- `conversation-command-review` 迁移到“安全与命令审批”。
- `conversation-memory` 迁移到“记忆、上下文与知识继承”。
- `conversation-mention` 迁移到“多数字员工协作”，并删除项目协作引导。

## 验收标准

- 产品手册显示九个一级模块，顺序与本设计一致。
- 所有 `itemIds` 都能解析到唯一文章，没有孤儿文章。
- 所有文章包含标题、流程图、实现逻辑和边界说明。
- 手册中不出现“项目协作”、Workflow Canvas 或引导用户使用该废案的文案。
- 现有产品手册页面和 Markdown 渲染方式保持可用。
