# Atolla 局域网优先中继设计

## 意图

让 iPhone Atolla App 在能直连 Mac 的局域网（包括 iPhone 个人热点）内直接完成现有全部移动端功能；不可达时自动继续使用当前腾讯云远程中继。腾讯云中继的接口、服务、数据库、部署和既有客户端协议均不修改。

## 目标与边界

- 覆盖实例列表、登录/解锁、Agent、会话、聊天、图片、任务队列、权限审批、设置、通知偏好和 JEV 等当前手机端功能。
- iPhone 前台优先连接 Mac；局域网无法发现、握手或请求连续失败时回退远程中继。
- 仅使用 HTTP，不购买或配置公网 HTTPS 证书。
- 局域网服务不复用或暴露现有 Mac 管理后台 API；默认关闭，显式启用且完成设备配对后才监听。
- 不保证 iOS 后台/锁屏时的局域网实时性；该场景仍由远程中继与推送承担。

## 已确认现状

- 远程中继当前由 `remote-relay/server` 提供，移动端使用 HTTP 长轮询，不是 WebSocket。
- 远程站点接口覆盖实例、会话、消息镜像、任务、审批、图片及设置等完整功能。
- Mac 后端当前默认仅监听回环地址；这是管理后台的安全边界，不能为了局域网功能改为直接对内网暴露。

## 方案选择

选择“协议复用层 + 局域网优先、远程回退”。

不选“Mac 模拟全部云端中继接口”：它会复制并长期维护云端协议，接口容易漂移，且会违反不触碰远程中继相关代码的维护目标。

## 架构

```text
iPhone App
  ├─ RelayTransport（统一上层业务调用）
  │   ├─ LanRelayTransport     → HTTP → Mac LAN Relay
  │   └─ RemoteRelayTransport  → HTTP → 现有腾讯云 Relay
  ├─ Bonjour 发现 / 二维码配对
  └─ 路由策略：LAN healthy 优先；失败退回 remote

Mac Desktop
  ├─ 既有回环管理后台（保持不变）
  ├─ 新增 LAN Relay 独立监听器
  ├─ 设备配对与设备密钥存储
  └─ LAN API Facade → 复用既有本地 Service / Store
```

### Mac LAN Relay

- 独立端口与 Gin 路由组，例如 `/lan/v1`；不能挂到现有面向桌面浏览器的 API 上。
- 只绑定启用的私网 IPv4/IPv6 接口；拒绝公网、回环外的非私网地址，禁止端口转发用途。
- 通过 Bonjour 广播 `_atolla._tcp`，TXT 仅包含协议版本、实例短 ID、端口和临时发现标识；不广播 Token、IP 外的隐私数据或设备密钥。
- 用 Facade 将现有本地业务能力映射成 LAN DTO；LAN DTO 与远程 Relay DTO 可以共享类型定义，但 URL、认证和传输实现独立。
- 对读取、写入、上传、审批和状态轮询分别限流；写操作要求幂等键，审批操作要求请求 ID 与版本/截止时间匹配。

### 配对与 HTTP 安全

HTTP 没有传输加密，局域网链路必须定位为受控网络功能：不在请求中明文传输长期密码或远程 Relay JWT。

1. Mac 创建一次性配对会话（短时、单次使用）。
2. iPhone 扫描二维码，取得 Mac 地址、端口、配对会话 ID 与随机挑战值。
3. 两端经一次性配对请求生成独立设备密钥，Mac 只保存该设备密钥摘要与权限范围；iPhone 存入 Keychain。
4. 后续每个请求带 `device_id`、时间戳、nonce、请求体摘要和 HMAC 签名；Mac 验签并缓存 nonce，拒绝重放、时钟漂移和失效设备。
5. 用户可在 Mac 端查看、撤销设备；撤销立即使密钥不可用。

这不能提供 HTTP 的内容保密性：同一网络的攻击者仍可读取内容。未来如需保密性，升级为自签名 TLS + App 证书指纹固定，不需要购买证书。

### iPhone 路由策略

- App 启动、前台恢复、网络变化后尝试 Bonjour 发现；已配对但发现失败时可使用上次地址进行短时健康检查。
- 健康检查和鉴权均成功后，将当前实例标记为 `lan`；失败连续达到阈值后切换为 `remote`，并使用退避重试 LAN。
- 路由以“实例”为单位，不以全局 App 为单位，避免一台 Mac 可局域网访问时影响其他远程实例。
- 上层页面只依赖 `RelayTransport` 能力接口，不感知当前网络通道；切换时取消旧轮询、保留幂等键，并从目标通道重新拉取最新快照。
- 明确展示“局域网直连 / 云端中继 / 正在回退”状态，允许用户强制选择“仅局域网”“自动”“仅云端”。

## 前端交互设计

### Mac 桌面端

入口保留在现有管理端导航的“远程中继”页面，避免新增一级导航；页面内明确分开本地与云端能力，不能将局域网设置混入腾讯云部署表单。

```text
远程中继
├─ 移动端连接策略
│  ├─ 自动（默认）：局域网优先，失败回退腾讯云
│  ├─ 仅局域网
│  └─ 仅腾讯云
├─ 局域网直连（Beta）
│  ├─ 启用开关与当前状态
│  ├─ 配对 iPhone：二维码 / 重新生成
│  ├─ 已配对设备：名称、最后在线、当前通道、撤销
│  └─ 高级项：端口、重新广播、仅允许已配对设备
└─ 腾讯云中继
   └─ 保留全部现有部署、状态、域名、密码、邮件和会话配置
```

- “局域网直连”关闭时仅展示说明和启用按钮；开启后再显示二维码、设备管理与高级项，避免表单堆叠。
- 状态同时使用文字和图标，至少区分“未开启、正在广播、iPhone 已连接、已回退云端、异常”，不可只靠颜色表达。
- HTTP 模式在局域网卡片内固定展示“仅适用于可信网络，内容不加密”的安全提示。
- 配对、撤销和重置属于高影响操作，需显示加载状态并对撤销提供二次确认。

### iPhone App

移动端不改变日常页面的信息架构；在“设置 → 连接”新增一个连接管理页，并在实例页/会话页顶部放置只读的当前通道状态。

```text
设置 → 连接
├─ 当前连接：局域网直连 / 腾讯云中继 / 正在切换 / 不可用
├─ 连接策略：自动（默认）/ 仅局域网 / 仅腾讯云
├─ 局域网直连
│  ├─ 扫描 Mac 配对二维码
│  ├─ 已配对 Mac 列表与当前 Mac
│  ├─ 重新发现 / 手动刷新
│  └─ 断开并移除此 Mac
└─ 云端中继
   └─ 保留现有登录、实例与解锁行为
```

- 首次使用自动策略时，若未配对 Mac，显示一个一次性的引导卡片：“扫描 Mac 上的二维码以启用局域网直连”；允许跳过，不阻断云端使用。
- 连通性从 LAN 切到云端时，用轻提示说明“局域网不可达，已切换至腾讯云”；不弹阻塞对话框，不丢失当前页面或输入框内容。
- “仅局域网”失败时展示可操作的排查项：确认 Mac 已开启局域网直连、两端在同一可通信网络、重新扫描二维码；不自动泄漏 Mac IP。
- 所有主要触控目标至少 44pt；状态标签支持 VoiceOver，网络切换动画遵循系统减少动态效果设置。

## 分期交付

1. **基础设施**：Mac LAN Relay 生命周期、私网绑定、Bonjour、配对、签名认证、设备管理、健康检查。
2. **全量业务 Facade**：按当前手机端 API 清单接入读取、命令、聊天、图片、任务、权限、设置和通知能力，补齐 DTO/契约测试。
3. **iPhone Transport**：增加 `RelayTransport`、LAN/远程实现与逐实例路由；远程实现保持调用现有接口不变。
4. **可靠性与验收**：普通 Wi-Fi、iPhone 热点、发现失败、切换网络、Mac 休眠恢复、撤销设备、重放攻击、并发审批与云端回退测试。

## 验收标准

- 远程 Relay 仓库的既有路由、数据库迁移和部署配置没有变更。
- 局域网可达时，抓取 iPhone 请求不出现腾讯云域名；所有手机端功能可完成。
- 局域网断开后，自动回退现有远程中继且不会重复创建聊天、任务或审批决定。
- 未配对设备、过期签名、重复 nonce、非私网来源均被拒绝并记录安全审计。
- iPhone 个人热点下，若系统允许直连则可工作；若 Bonjour 被限制，二维码地址和健康检查仍可建立连接。

## 尚待实现阶段确定的事项

- iPhone App 实际原生容器及其 Bonjour/二维码库选型。
- LAN API 的最终 DTO 归属位置与远程 Relay DTO 的共享方式。
- 局域网 HTTP 内容保密性是否需要在首版即采用自签名 TLS。
