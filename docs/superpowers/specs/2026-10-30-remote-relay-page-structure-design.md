# 远程中继页面结构优化设计

## 目标

将服务器部署、远程连接、验证码登录拆成独立区块，并按前置依赖顺序展示。部署日志只在任务触发后显示，切换菜单不丢失，任务结束 10 分钟后自动清除。

## 方案

- 页面顺序：服务器部署 → 部署进度（按需）→ 远程连接配置 → 验证码登录配置 → 运行状态 → 移动端访问。
- `RemoteRelayPanel` 在管理台内保持挂载，仅通过 `active` 隐藏；部署 SSE 在切换菜单后继续运行。
- 日志仅保存在 React 内存状态中。任务运行期间不清理；成功或失败后启动 10 分钟定时器，届时清除日志、状态和任务类型。
- SMTP 仍复用现有配置接口，但从连接表单中拆成独立卡片，操作和校验逻辑不变。

## 边界

- 不新增后端接口或持久化表。
- 刷新浏览器、退出管理台或重启前端后日志立即消失。
- 已由用户手动部署的中继无法可靠检测，因此只调整流程顺序，不强制锁死后续配置。

## 备选方案

- `sessionStorage`：刷新后仍保留，但可能存入敏感部署输出且超出“短时留存”范围，不采用。
- 后端日志持久化：跨页面最稳定，但需要新增生命周期与清理机制，成本过高，不采用。
