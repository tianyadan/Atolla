# iOS 双连接首次进入设计

## 意图

首次安装 iPhone App 时，用户应先选择连接方式，而不是先被要求填写中继地址和站点密码。局域网用户扫描 Mac 端二维码后即可进入已配对实例；远程用户继续使用现有中继地址和站点密码登录。

## 目标与边界

- 提供同等清晰的“局域网连接”和“远程连接”入口。
- 局域网二维码包含实例信息；扫码、配对、签名连通性检查成功后直接进入该实例。
- 局域网配对密钥只进入 iOS Keychain；前端仅保存该实例的非敏感选择状态。
- 已有远程登录、局域网设置页、云端中继接口和配对协议保持兼容。
- 本次不改变二维码协议，不把长期密钥放入二维码，也不让 LAN 请求绕过服务端 HMAC 验证。

## 现状与关键约束

- 当前 `/login` 只有 Relay API 和 Site password，且 `RequireAuth` 只承认云端 site token。
- QR 配对已经会取得 `instance_id`、设备 ID 和设备密钥，且 LAN Facade 已支持实例、Agent、消息、任务等主要读取和动作。
- 配对是按实例隔离的；不能把某个实例的 LAN 密钥用于其他实例。
- 没有远程配置时，局域网模式不能静默回退到云端；否则会得到不可理解的网络错误。

## 方案选择

### 方案 A（采用）：双路径入口 + 本地连接会话

首次页显示两张可点击的连接卡：

1. **局域网连接**：调用原生扫码 → 消费二维码配对 → Keychain 保存密钥 → 签名 health 校验 → 写入 `lan` 本地连接会话 → 进入二维码所属实例。
2. **远程连接**：进入现有地址/密码表单，登录成功后写入 `remote` 会话。

`RequireAuth` 认可远程 token 或有效的本地 LAN 会话。它只控制前端路由；每条 LAN API 仍由服务端 HMAC 验证，不能把本地状态当作安全凭据。LAN 首次配对默认为 `lan_only`，用户后续在“中继与连接”添加远程地址后，才可改为“局域网优先并回退云端”。

### 方案 B：扫码后仍要求远程密码

改动较小，但不能离线/纯局域网进入，违背目标，舍弃。

### 方案 C：为 LAN 额外签发云端 JWT

会把本地配对和云端账户绑定，扩大攻击面且破坏“无需云端”的目标，舍弃。

## 页面与交互

### 首次连接页

- 保留品牌区，标题为“连接到 Atolla”。
- 局域网卡为主操作：说明“扫描 Mac 上的二维码，不需要服务器地址或密码”；点击后请求相机并显示可取消的扫描状态。
- 远程卡为次操作：说明“使用中继服务器，从任何网络访问”；点击后卡片平滑展开地址和密码表单。
- 动效只使用 opacity/transform：品牌进入、卡片 40ms 错峰淡入、展开/收起 220ms；按下缩放反馈。所有动效尊重 `prefers-reduced-motion`。
- 扫码、配对、校验分别展示明确状态；失败提示原因和“重试/改用远程连接”。不通过颜色单独表达状态，按钮最小触达面积 44px。

### 后续入口

- 已经配对但未配置远程时，启动 App 直接恢复 LAN 实例。
- 设置保留“中继与连接”：可添加远程中继、测试 LAN、移除配对、切换策略。
- 退出登录只清理远程 token；LAN 配对需在设置中显式移除，避免误删 Keychain 密钥。

## 前端状态与路由

- 新增 `connectionSession`：`{ mode: 'lan', instanceId }`，只在配对+health 成功后写入；无密钥、过期配对或 health 失败时清除。
- 新增 `hasAuthenticatedConnection()`：远程 token 存在或 LAN 会话对应的完整配对存在时为真；替换 `RequireAuth` 的 token 单一判断。
- 登录页成功 LAN 配对后跳转 `/instances/:instanceId`，而不是通用首页，保证首屏就是扫描到的 Mac。
- LAN-only 未映射的请求必须给出“此功能需要配置远程中继”的可恢复提示，不能调用空云端地址。

## 验收与测试

1. 无任何配置时，首次页显示两个入口；不显示远程字段。
2. 扫码成功、health 成功后，无中继地址/密码仍可进入二维码所属实例并加载核心 LAN 支持页面。
3. 扫码取消、相机拒绝、二维码过期、Mac 不可达均留在首次页并显示可恢复错误。
4. 远程登录路径回归通过；已有 token 用户不看到首次连接页。
5. LAN 会话缺少匹配 Keychain/local 配对时不放行受保护路由。
6. 通过单元测试覆盖会话判定与失败清理；完成 Web 构建、Capacitor sync 和 iOS 模拟器构建。真机需覆盖相机授权、同 Wi-Fi、iPhone 热点三种网络。

## 实施规模

中等：前端登录与路由守卫、LAN 请求错误边界、文案和 CSS 动效为主；不改变云端接口或二维码加密协议。
